# AI providers and models

Every model IncidentLens can call, what it is used for, and whether the call is
orchestrated through Genblaze or made directly. Required reading for anyone
auditing the provenance manifests.

## In the shipped demo

These run when you reproduce the four gallery incidents with the documented
command (`incidentlens studio <scenario> --voice genblaze --narration llm
--narration-provider openai --narration-model gpt-4o`).

| Provider | Model | Role | Modality | Via Genblaze? |
| --- | --- | --- | --- | --- |
| OpenAI | `gpt-4o` | Writes the narration script from the deterministic analysis | text | No — direct `openai` SDK |
| OpenAI | `gpt-4o-mini-tts` | Speaks each narration beat | audio | **Yes** — `genblaze_openai.OpenAITTSProvider`, one `generate` step per beat (14–17 per video), `prompt_visibility=private` |

Each rendered video therefore carries two Genblaze manifests:

- `replay.narration.genblaze.json` — 14–17 `generate` steps, provider
  `openai-tts`, model `gpt-4o-mini-tts`, modality `audio`, each with a SHA-256
  of the produced audio.
- `replay.genblaze.json` — a single `ingest` step with `provider: null`,
  recording the finished MP4 (SHA-256, dimensions, duration, codec, tracks)
  plus a digest of the analysis document that produced it.

The `ingest` step is deliberate: the video is **not** model-generated, so it is
recorded as provenance-tracked media rather than claimed as a generation.

## Selectable alternatives

Supported and wired up, but not used in the shipped demo.

| Provider | Model | Role | Via Genblaze? | How to select |
| --- | --- | --- | --- | --- |
| Anthropic | `claude-sonnet-5` (default), `claude-opus-4-8` | Narration script | No — direct `anthropic` SDK | `--narration llm --narration-model claude-sonnet-5` (needs `ANTHROPIC_API_KEY`) |
| OpenAI | `gpt-4o-mini-tts` | Narration voice, direct | No — direct `openai` SDK | `--voice openai` |
| ElevenLabs | `eleven_turbo_v2_5` | Narration voice | No — direct REST | `--voice elevenlabs` |
| Piper (open source) | any `.onnx` voice | Narration voice, fully offline | No — local subprocess | `--voice piper` |
| espeak-ng (open source) | n/a | Narration voice, offline fallback | No — local subprocess | `--voice offline` |

Any OpenAI-compatible gateway can be substituted for hosted OpenAI by setting
`INCIDENTLENS_OPENAI_BASE_URL`.

## Used once, outside the pipeline

| Provider | Model | Role | Via Genblaze? |
| --- | --- | --- | --- |
| OpenAI | `sora-2-pro` | A 4-second decorative title clip (`demo/incidentlens-sora-opener.mp4`) | No — generated by a direct API call before the Genblaze integration existed |

Stated plainly because it is the one generated asset that does **not** carry a
Genblaze manifest. It is optional, is not part of any incident replay, and is
not evidence of Genblaze usage.

## What uses no model at all

The parts of IncidentLens that make factual claims are deterministic by design,
because a generative model must not be able to invent a service name, a
dependency edge, or an evidence citation:

- **Incident reconstruction** — origin detection, failure propagation, blast
  radius, hypothesis confidence and the `confirmed` / `inferred` / `unknown`
  labels are computed by `engines/deterministic.py`. The engine raises rather
  than emit a citation it cannot resolve.
- **Static code analysis** — the module and function call graphs come from
  Python `ast` parsing. Nothing is imported or executed.
- **The 3D replay itself** — every frame is rendered locally from the analysis
  document. Identical input produces byte-identical pixels.

The language model writes *prose about* the analysis. It never produces the
analysis.
